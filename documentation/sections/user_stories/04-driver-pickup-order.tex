\subsubsection{User Story 4: Driver Pickup Order}

% TODO: Add content

\paragraph{Description}
As a driver, I want to pick up an assigned order so that I can begin the delivery process for the client.

\paragraph{Actors}
\begin{itemize}
    \item Driver
    \item API Gateway
    \item Delivery Service
    \item Order Service
    \item Notify Service
\end{itemize}

\paragraph{Sequence Diagram}

\paragraph{Business Details}
The driver requests a batch of delivery assignments. The system retrieves the oldest pending delivery order from the CMS, builds a multi-stop optimised route by finding geographically nearby pending orders from an in-memory route index, marks all selected orders as collected, and pushes the ordered route to the driver via WebSocket.

\paragraph{Implementation Details}
The driver issues a POST /deliveries \{count\} carrying a driver JWT. The Delivery Service publishes order.delivery.request\_next through the Order Service to the CMS adapter (GetNextPendingDelivery SOAP call). The Route Service maintains an in-memory orderLocationIndex by listening for order.status\_updated events; it uses this index to select up to count - 1 nearby orders as additional stops. The combined stop list is sent to the ROS adapter (Route Optimisation Service) via POST /api/ros/optimize-route, which returns an optimised path. For each order in the path, the Delivery Service fires parallel AMQP events to mark the WMS delivery status as on\_route and the CMS order status as collected. Once all acknowledgements are received, the optimised route is pushed to the driver as a driver\_route WebSocket message.
