\section{Prototype Implementation}
\label{sec:prototype}

The prototype implements the described architecture using containerised Node.js services. All core flows—order creation, delivery assignment, and real-time WebSocket notifications are operational. No client UI is included thus all interaction is through the integration test suite. The three legacy systems (CMS, ROS, WMS) are replaced by lightweight mock servers that replicate the same interfaces over SOAP, REST, and REST respectively.

\subsection{Running the Prototype}
\label{subsec:setup}

\begin{lstlisting}[language=bash]
# 1. Build and start all 13 containers
docker compose up --build

# 2. Verify the gateway is up
curl http://localhost:8081/health   # {"status":"ok"}
\end{lstlisting}

\subsection{Running the Tests}
\label{subsec:testing}

The integration test suite in \texttt{source-code/tests/} covers all core flows. Node.js is required on the host.

\begin{lstlisting}[language=bash]
cd source-code && npm install

# Run all tests sequentially
node tests/test-all.js

# Or run a specific flow
node tests/test-order-workflow.js
node tests/test-delivery-complete.js
\end{lstlisting}

The suite includes six test files: authentication, full order lifecycle, driver delivery workflow, delivery completion, delivery status query, and order history. Each test creates a unique user to avoid state collisions between runs.

\subsection{Limitations}
\label{subsec:limitations}

\begin{itemize}
    \item No client-facing UI; interaction is via the test suite. 
    \item No TLS only using plain HTTP/WS.
    \item Services use a in memory data variable instead of a in memory database like Redis 
    \item Payment processor is simulated with a dummy provider with a success rate of 90\% to allow testing of compensating flows.
\end{itemize}
